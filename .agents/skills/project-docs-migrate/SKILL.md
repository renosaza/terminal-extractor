# Migrate project documentation

## Execution role

Honor the active session role and higher-priority instructions. In an explicitly identified Astra/Sol orchestrator session, delegate searches to Luna (choose effort for the task) and file changes/checks to a Terra worker; integrate evidence without editing files yourself. Workers execute their assigned scope directly without recursive delegation. Terra and lower-tier main sessions execute directly. Do not infer the running model from a config default, invent model IDs, or silently switch roles when delegation is unavailable; report the limitation and request an explicit direct-work override. Keep delegated briefs bounded and require sources, changed paths and actual check results.

Create a reviewable migration of project knowledge. Read [references/layout.md](references/layout.md) for the target contract; do not load unrelated documents.

1. Inspect existing AGENTS.md, documentation entrypoints, source formats and the canonical remote/tracker. Inventory readable sources and their revisions/locations. Use available format readers; report inaccessible, encrypted, undecodable or OCR-dependent material precisely without claiming to have converted it.
2. Map durable facts to architecture, ADRs, debt, tasks and human guides. Extract explicit current prohibitions into docs/constraints.md with sources and scope; preserve disputed or obsolete restrictions separately as unresolved/history, not new active rules. A requested OKF migration authorizes necessary metadata edits in place; preserve originals in existing Git history, or make a backup outside the docs bundle when no recoverable history exists, with a source-to-destination mapping. Do not leave untyped duplicate Markdown or raw transcripts inside the OKF bundle. Use relative source links or stable URLs plus source revision/section so each migrated decision and status is traceable. Summarize knowledge rather than copy entire chat/export histories.
3. Merge by meaning and stable identity. Preserve accepted decisions, ownership, dependencies and unresolved disagreements. Do not infer acceptance from implementation alone. Preserve original status in provenance if the schema needs mapping; unknown validation stays unknown. If the schema cannot represent an unknown status, retain the item in the migration note rather than inventing `accepted`, `done` or another status. An imported completion claim may remain historical `done` only with Result attributing the claim to its source and explicitly stating that it was not revalidated. Never present it as a fresh successful check.
4. Write the smallest target files supported by evidence. Retain existing AGENTS.md instructions and merge only required routing, including reading active docs/constraints.md rules before implementation. Preserve the project's language rule. Where canonical destinations already exist, reconcile instead of overwriting. Keep conflicting assertions with their sources and the precise unresolved question; ask only when it blocks a consequential choice.
5. Keep the current tracker authoritative unless a tracker migration was requested. Do not open/close issues or rewrite remote history as a side effect. Record any source-to-destination mapping and unresolved gaps in a concise migration note only when needed to audit the conversion.
6. Migrate the docs tree to OKF v0.2: every Markdown file except index.md/log.md is a concept with YAML `type`. Rename legacy workflow `status` to task_status (tasks/epics), decision_status (ADRs) or debt_status (debt); reserve status for OKF lifecycle. Preserve custom IDs and mapping from previous paths; never infer human verification from imported claims. Concept identity is its bundle path without .md; custom `id` remains the stable workflow identity. Repair affected incoming links when moving concepts. Keep normal relative links for GitHub readability. Check links, IDs, dependencies, provenance and status evidence. Report migrated coverage and remaining unread/unresolved material. Do not remove source files unless the user requested removal and preservation has been verified.
