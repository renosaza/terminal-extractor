# Проверить Ghostty dictionary и текстовый экспорт

## Результат

Получить version-specific capability matrix для stable surface IDs, new/configuration, addressed input text/send key, screen/scrollback export и optional AX text.

## Приёмка

Сопоставлены установленный release и текущий source dictionary. Отдельно проверены pid/tty, key semantics и returned export path. Clipboard side effect, отсутствие atomic read и retained-history limits записаны. Не объявлять всё поддержанным только по минимальному номеру 1.3.0.

## Проверка

PARTIAL: установленный словарь и версия прочитаны; несколько windows/tabs/splits, неактивная surface, clipboard opt-in/отказ, temporary-file lifecycle, alternate screen и Unicode — `NOT_RUN`. Исследовать без screenshot/OCR и без paste filepath в программу. AT-03/04/15/17, TE-C01/03/04/06.

## Фактический результат и продолжение

На macOS 27.0 (26A428) установлен Ghostty 1.3.1 (build 15212). `python3 probes/dictionaries.py` прочитал встроенный `Ghostty.sdef`, SHA-256 `0ac1bbd8e6fdc7e2ca36cee6b31bc95b2b9e6a4643560d6833c1e031aa022adf`. Словарь объявляет стабильные текстовые `id` для window/tab/terminal, `new window`, `new tab`, `split`, адресные `input text ... to terminal`, `send key ... to terminal` и `perform action ... on terminal`. У terminal объявлена `working directory`, но **нет `pid` и `tty`**. [Текущий исходный словарь Ghostty](https://github.com/ghostty-org/ghostty/blob/4ae9f1a2de5484de3d6a13fe03676b8853b9c41c/macos/Ghostty.sdef) уже содержит `pid`/`tty`: нельзя приписывать их установленному 1.3.1. Это `known` для декларации API, семантика ввода ещё `not_tested`.

Экспорт screen/scrollback и возвращаемый путь `NOT_RUN`: SDEF даёт общий `perform action`, но не перечисляет действия и их побочные эффекты. Clipboard не трогался, Apple Events/TCC не запрашивались. Следующий шаг — тестовые windows/tabs/splits и адресные вызовы; экспорт — только при отдельном opt-in, с фиксацией изменения clipboard и жизненного цикла временного файла. Проверенный исходный revision: `6dee2b5` плюс текущие изменения ветки `te-e01`.
