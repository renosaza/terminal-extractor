# Проверить Ghostty dictionary и текстовый экспорт

## Результат

Получить version-specific capability matrix для stable surface IDs, new/configuration, addressed input text/send key, screen/scrollback export и optional AX text.

## Приёмка

Сопоставлены установленный release и текущий source dictionary. Отдельно проверены pid/tty, key semantics и returned export path. Clipboard side effect, отсутствие atomic read и retained-history limits записаны. Не объявлять всё поддержанным только по минимальному номеру 1.3.0.

## Проверка

PARTIAL: установленный словарь и версия, test window/tab/split, неактивная surface и clipboard export проверены. Clipboard conflict/отказ, alternate screen, Unicode и полная долговечность временных файлов — `NOT_RUN`. Исследовать без screenshot/OCR и без paste filepath в программу. AT-03/04/15/17, TE-C01/03/04/06.

## Фактический результат и продолжение

На macOS 27.0 (26A428) установлен Ghostty 1.3.1 (build 15212). `python3 probes/dictionaries.py` прочитал встроенный `Ghostty.sdef`, SHA-256 `0ac1bbd8e6fdc7e2ca36cee6b31bc95b2b9e6a4643560d6833c1e031aa022adf`; хеш совпал с [tag v1.3.1](https://github.com/ghostty-org/ghostty/blob/v1.3.1/macos/Ghostty.sdef). Словарь объявляет стабильные текстовые `id` для window/tab/terminal, `new window`, `new tab`, `split`, адресные `input text ... to terminal`, `send key ... to terminal` и `perform action ... on terminal`. У terminal объявлена `working directory`, но **нет `pid` и `tty`**. [Текущий исходный словарь Ghostty](https://github.com/ghostty-org/ghostty/blob/4ae9f1a2de5484de3d6a13fe03676b8853b9c41c/macos/Ghostty.sdef) уже содержит `pid`/`tty`: нельзя приписывать их установленному 1.3.1. Это `known` для декларации API, семантика ввода ещё `not_tested`.

После разрешения Apple Events `new window` вернул `tab-group-779f4164e0`, `tab-779d6ae000` и surface `7638A394-5D9B-478B-9F12-97A0AA7761D5`. `input text` оставил команду без исполнения; отдельный `send key "enter"` создал ожидаемый marker. `split ... direction right` вернул surface `BA5D7F90-84B6-4292-92E5-3972DB152533`; она осталась focused, пока адресный ввод в первую surface выполнился именно там. `new tab in w` вернул отдельный tab/surface ID. Тестовое окно закрыто, исходное пользовательское окно не использовалось для ввода.

С отдельным согласием на проверки `perform action "write_screen_file:copy"` и `write_scrollback_file:copy` вернули `true`, поменяли clipboard на путь к regular file владельца; [probe](../../../probes/ghostty/export.swift) сохранил и восстановил clipboard representations. Первый screen-файл содержал тестовые markers. После 60 строк scrollback-файл содержал `fill1`, но не `fill60`; повторный screen-файл содержал обе — это разные snapshots, не атомарное чтение и не непрерывный журнал. Файлы ещё существовали после закрытия окна; шесть созданных проверкой файлов удалены явно. Clipboard conflict, сторонние watchers и полное восстановление всех нестандартных representations не доказаны. Путь не вставлялся в terminal. [Документация Ghostty](https://ghostty.org/docs/config/keybind/reference) описывает эти actions; минимум версии нельзя выводить из одного номера release. Проверенный revision: текущая ветка `te-e01` до фиксации результатов.
