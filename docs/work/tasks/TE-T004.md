# Подтвердить stack и границу первого релиза

## Результат

Минимальный Swift MCP stdio прототип и tmux capture proof; таблица реальных SDK/protocol/macOS/tmux versions; обновлённый proposed ADR с evidence.

## Приёмка

Version negotiation работает с выбранным client, structured output bounded. Проверена возможность capture-before-shell, screen state и отдельного tmux namespace. Выбраны проверяемые dependency pins и minimum versions. Native blockers не скрываются переходом на managed; принимается точный release scope без ложного full Existing.

## Проверка

NOT_RUN: start/stop gateway, длинная output stream, isolated tmux session, SDK/tool schema roundtrip. Зафиксировать raw results и альтернативы при blocker. Не добавлять cloud/DB service. AT-12/17, TE-C01..04/06/08.

## Фактический результат и продолжение

На стенде macOS 27.0 (26A428, Apple M5) доступен Swift 6.4 (`swift --version`), но `tmux` отсутствует (`command -v tmux` завершился без пути). Системные зависимости не устанавливались по TE-C06. Последний опубликованный релиз официального Swift MCP SDK на момент проверки — [0.12.1](https://github.com/modelcontextprotocol/swift-sdk/releases/tag/0.12.1), исходный commit `a0ae212ebf6eab5f754c3129608bc5557637e605`; его `Package.swift` требует Swift tools 6.1, а `Version.supported` перечисляет `2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`. Поддержка `2026-07-28` этим release не заявлена. Это проверка исходников SDK, не runtime negotiation.

Блокеры: TE-T001..003 ещё не закрыты; для tmux capture нужен установленный tmux, для SDK roundtrip — проектная загрузка SwiftPM dependency. Оба действия ожидают отдельного локального разрешения по TE-C06. До этого Swift MCP/tmux proof остаётся `NOT_RUN`; release scope и version pins не утверждены. Следующий шаг — после снятия блокеров минимальный stdio/tool-schema probe и отдельный namespace tmux с capture-before-shell. Проверенный исходный revision: `6dee2b5` плюс текущие изменения ветки `te-e01`.
