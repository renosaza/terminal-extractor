# Ghostty: безопасный opt-in text export

## Результат

Реализовать addressed write_screen_file/write_scrollback_file copy action, private file validation и честную clipboard transaction.

## Приёмка

Нет OCR/screenshots/paste filepath/open editor. Согласие отдельно от read grant. Path не принимается без owner/regular-file/no-symlink/size/fstat проверки; arbitrary file read запрещён. Screen и scrollback — разные non-atomic snapshots, не полный stream. Clipboard конфликт fail closed; чужое изменение не перезаписывается намеренно. Остаточная non-atomic race и watchers exposure указаны.

## Проверка

PARTIAL: 2026-09-24 `swift build`, `swift run TermexIPCCheck`, `swift run TermexExportFileCheck`, `python3 Tests/integration/check.py`, `git diff --check` PASS. Синтетические проверки покрывают IPC-ответ длиннее 255 байт, свежий private `screen.txt`, выход из root, старый файл, symlink и превышение 16 KiB; интеграция отклоняет `terminal_screen` без grant/token. Живой MCP-вызов после отдельного согласия вернул снимки трёх разных Ghostty surface: 151, 147 и 112 символов, `source=ghostty_screen_snapshot`, `history_complete=false`. Текст экрана в тестовый вывод не попадал. Буфер после теста не содержал путь экспорта, но точное восстановление исходных типов/данных до и после отдельно не сравнивалось. Конкурентный clipboard writer, deferred provider, timeout, Stop во время export и большой реальный export — NOT_RUN. Оригинальный файл не удаляется. AT-04/14/17, TE-C01/04/06/07/09.

## Фактический результат и продолжение

Добавлен одноразовый `terminal_screen` для выбранной Ghostty surface при двух разрешениях: локальный read/control scope и отдельная отметка clipboard export. Опция `native_ghostty_clipboard_export` в private config по умолчанию выключена. Gateway хранит token внутри connection; host проверяет peer executable, token, generation, scope и epoch до адресного действия и после него. Файл открывается через private temp directory FD с `O_NOFOLLOW`, ограничением размера и повторным `fstat`. Живой тест выявил каталог Ghostty `0755` внутри private temp root `0700` и эквивалентные пути `/var` и `/private/var`; validator принимает этот layout, но отклоняет group/other writable directory. Живой ответ >255 байт выявил trap при упаковке заголовка IPC; исправлено через `UInt8(truncatingIfNeeded:)` и покрыто 300-байтовым frame check. Clipboard сохраняется в памяти и восстанавливается только при неизменном `changeCount`/path; универсального атомарного CAS нет. Ошибки до восстановления могут оставить экспортированный путь в clipboard, поэтому дальнейшая приёмка обязательна до объявления адаптера стабильным.

Установленный Ghostty 1.3.1 создаёт два не закрываемых directory FD на успешный export по [исходнику релиза](https://github.com/ghostty-org/ghostty/blob/v1.3.1/src/Surface.zig#L5494-L5497) и [TempDir](https://github.com/ghostty-org/ghostty/blob/v1.3.1/src/os/TempDir.zig#L20-L63). Продукт ограничивает export до одного раз в 5 секунд и 64 на app instance за жизнь host; это ограничение не переживает перезапуск host. Частый polling на этом релизе не поддерживается. Следующий шаг — проверить точное восстановление clipboard и Stop во время export на безопасном тестовом окне; затем оценить исправленный релиз Ghostty. `write_scrollback_file` ещё не реализован.
