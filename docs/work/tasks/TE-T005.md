# Создать минимальный Swift host/gateway foundation

## Результат

Ввести реальные SwiftPM manifests, core interfaces, gateway/host separation и bounded local IPC; зафиксировать зависимости и фактические команды сборки/тестирования.

## Приёмка

Gateway не владеет shell; long-lived host отделён от клиентского процесса. IPC framing имеет limits/timeouts и корректный shutdown. Логи gateway не попадают в stdout protocol. Нет необязательного Python/ML runtime в core и искусственной инфраструктуры.

## Проверка

PARTIAL: `swift build` собирает product package; `python3 Tests/integration/check.py` проверяет отдельные host/gateway процессы, invalid/oversize framing, повторное подключение, private socket mode и cleanup по SIGTERM. GUI host, peer identity/grants, command/session interfaces, host crash/recovery и реальные MCP-клиенты ещё `NOT_RUN`. TE-C04/06/08, AT-12/17.

## Фактический результат и продолжение

Реальный [SwiftPM manifest](../../../Package.swift) закрепляет MCP Swift SDK 0.12.1. `termex-host` владеет только private Unix socket; `termex-mcp` обращается к host перед запуском MCP stdio. Gateway не владеет shell, stdout отдан MCP. С TE-T006 gateway объявляет только read-only `terminal_capabilities` с `terminal_access=false`. IPC использует 4-байтовую длину, предел 64 KiB и 5-секундный общий deadline на frame; host обслуживает запросы последовательно. Каталог и socket требуют owner и private mode. Корректный SIGTERM завершает host и удаляет socket. Аварийный выход может оставить stale socket: восстановление ещё не реализовано. Это только foundation: запросы не выдают права и не передают терминальные данные.

Следующий шаг — TE-T006 настройки, затем TE-T007 peer-checked grants и TE-T008 bindings; до этого нельзя выдавать runtime за пригодный для управления сессиями. Проверено на ветке `te-e02` до финального commit: `swift build` и `python3 Tests/integration/check.py`.
