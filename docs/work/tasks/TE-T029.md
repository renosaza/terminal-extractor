# Формализовать MCP schemas и error contract

## Результат

Создать исполняемые JSON Schemas/Swift модели для tools из API contract, nullable evidence/state/coverage и bounded error envelopes.

## Приёмка

Все поля, enum, limits и additionalProperties правила определены; synthetic examples либо валидируются, либо заменены полными fixtures. JSON-RPC error отделён от tool failure и nonzero command result. Tool annotations не считаются ACL; clipboard-read side effect честно отмечен. Version negotiation согласован с SDK.

## Проверка

NOT_RUN: roundtrip всех tools, invalid target/extra keys/large payload, null vs zero, protocol versions и минимальный compatibility text projection без двойного output. AT-05/08/16/17, TE-C04/05/07.

PARTIAL: `6f5fa60`, 2026-09-24 `python3 Tests/release_check.py` и `python3 Tests/integration/check.py` — PASS для release success/replay/conflict, отсутствующего grant, неверного UUID, generation, request_id и extra keys. Это не conformance всех будущих tools. YAML затронутых карточек/контракта разобран Ruby Psych; локальные ссылки и `git diff --check` — PASS.

## Фактический результат и продолжение

2026-09-24 контракт сопоставлен с наблюдаемой парой Codex `exec_command`/`write_stdin` и официальными App Server/approval/integrated-terminal docs; источники и пределы проверки находятся непосредственно в [контракте](../../architecture/mcp-contract.md). Разделены реализованный foundation, каталог будущих операций и предлагаемая компактная пара execute/continue. Наличие API App Server не объявляется доступом модели к существующей native pane. Текущий срез формализует только `terminal_release` с TargetRef/request_id, строгими входными полями и bounded replay; остальные полные schemas, общий error envelope и command continuation ещё не реализованы.
