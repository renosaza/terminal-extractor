# Session registry и устойчивые bindings

## Результат

Разделить session_id/generation/capture_epoch/shell_epoch и GUI view binding, реализовать discovery handles и lifecycle reconciliation.

## Приёмка

Title/index/PID/TTY отдельно не считаются полной identity. App instance и target проверяются перед вводом. Closing/reuse не превращает старый ID в новое окно; generation меняется при потере идентичности. Per-session capabilities хранится с provenance/version.
При нескольких доступных окнах/вкладках/splits discovery возвращает отдельные различимые строки; выбор требует конкретный opaque handle. Совпадающие title и отсутствие выбора не запускают attach к первому или focused target. Расположение окон на разных мониторах и перенос между ними не меняют binding; номер дисплея не служит identity или fallback при выборе.

## Проверка

PARTIAL: локальный Ghostty discovery проверен при двух окнах: отдельные строки, exact ID resolution и отказ после закрытия выбранного тестового окна. Проверка `python3 Tests/integration/ghostty_discovery.py` покрывает текущие строки и несуществующий surface ID. Одноразовый `keys_probe.py` отдельно подтвердил адресный Tab в двух splits и двух tabs без ввода соседу, а также отказ старым ID после закрытия split/tab. `TermexRegistryCheck` PASS для одноразового handle, двух targets с одинаковыми titles, повторной привязки той же цели к одному session ID, отказа старой generation и invalidation во время проверки. Локальный Terminal.app discovery проверен на fixture windows: explicit window ID/TTY, неверный TTY и старая app instance после завершения отклонены. Живой AppKit dialog показал пустой выбор по умолчанию; первый запрос завершился `unavailable` после таймаута, повторный выбор строки и `scope=read` вернул конкретный session ID/generation. Другой IPC connection не увидел выбор. TTY reuse, rename/reorder в живом приложении, перенос между мониторами, capture/shell epochs и persistence — NOT_RUN. Непереданные targets не раскрываются через MCP/IPC. AT-02/03/12/17, TE-C03/04/07.

## Фактический результат и продолжение

Host поддерживает локальные list/resolve diagnostics для запущенных Ghostty и Terminal.app. Apple Events адресуются к PID уже запущенного приложения; title/index не route key. Terminal.app tab TTY не равен устойчивой identity и может переиспользоваться. CLI diagnostic может показывать названия непереданных окон локальному пользователю, поэтому MCP/IPC его не вызывают. Core `SessionRegistry` хранит in-memory Ghostty selection handles со 120-секундным TTL, одноразовым потреблением, точными app/window/tab/surface IDs и локальными session ID/generation. Host подключает его к AppKit выбору с 90-секундным сроком: без явно выбранной строки нет привязки; `bindApproved` заново разрешает точную цель. Непереданные строки не уходят в MCP/IPC. На ошибке проверки старая привязка инвалидируется; повторный выбор получает новый session ID. Захват/reuse одинаковых native IDs между двумя наблюдениями пока не исключён. Persistent registry, Terminal.app attach и terminal read/input отсутствуют.

Следующий шаг — authenticated gateway, Stop и grants/lease с повторной проверкой непосредственно у dispatch. `revalidate` сейчас только read-only проверка идентичности и не удерживает разрешение на будущий side effect. Terminal.app attach остаётся закрытым до доказательства lifetime identity вкладки. Ghostty discovery проверена в ревизии `58c1323`, Terminal.app discovery — в `7fa8e76`; модель registry и локальный выбор — на ветке `local-client-connections`.
