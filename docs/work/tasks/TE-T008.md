# Session registry и устойчивые bindings

## Результат

Разделить session_id/generation/capture_epoch/shell_epoch и GUI view binding, реализовать discovery handles и lifecycle reconciliation.

## Приёмка

Title/index/PID/TTY отдельно не считаются полной identity. App instance и target проверяются перед вводом. Closing/reuse не превращает старый ID в новое окно; generation меняется при потере идентичности. Per-session capabilities хранится с provenance/version.
При нескольких доступных окнах/вкладках/splits discovery возвращает отдельные различимые строки; выбор требует конкретный opaque handle. Совпадающие title и отсутствие выбора не запускают attach к первому или focused target.

## Проверка

PARTIAL: локальный Ghostty discovery проверен при двух окнах: отдельные строки, exact ID resolution и отказ после закрытия выбранного тестового окна. Проверка `python3 Tests/integration/ghostty_discovery.py` покрывает текущие строки и несуществующий surface ID. Terminal.app, несколько tabs/splits, rename/reorder, одинаковые titles, app restart, generation/capture/shell epochs, persistent registry и локальный consent — NOT_RUN. Непереданные targets не раскрываются через MCP/IPC. AT-02/03/12/17, TE-C03/04/07.

## Фактический результат и продолжение

Host поддерживает только локальные `--list-ghostty` и `--resolve-ghostty`: read-only enumeration всех запущенных Ghostty windows/tabs/surfaces и повторную проверку полного app-instance/window/tab/surface ID. Apple Events адресуются к PID уже запущенного приложения; title/index не route key. CLI diagnostic может показывать названия непереданных окон локальному пользователю, поэтому MCP/IPC его не вызывают. Session ID, grants и attach пока отсутствуют.

Следующий шаг — локальный выбор и consent, затем host-owned registry/opaque handle с generation, перепроверкой binding перед чтением/вводом и adapter для Terminal.app. Проверена ревизия `58c1323` на ветке `te-e02`.
