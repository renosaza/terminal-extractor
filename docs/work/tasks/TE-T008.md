# Session registry и устойчивые bindings

## Результат

Разделить session_id/generation/capture_epoch/shell_epoch и GUI view binding, реализовать discovery handles и lifecycle reconciliation.

## Приёмка

Title/index/PID/TTY отдельно не считаются полной identity. App instance и target проверяются перед вводом. Closing/reuse не превращает старый ID в новое окно; generation меняется при потере идентичности. Per-session capabilities хранится с provenance/version.
При нескольких доступных окнах/вкладках/splits discovery возвращает отдельные различимые строки; выбор требует конкретный opaque handle. Совпадающие title и отсутствие выбора не запускают attach к первому или focused target.

## Проверка

PARTIAL: локальный Ghostty discovery проверен при двух окнах: отдельные строки, exact ID resolution и отказ после закрытия выбранного тестового окна. Проверка `python3 Tests/integration/ghostty_discovery.py` покрывает текущие строки и несуществующий surface ID. Локальный Terminal.app discovery проверен на fixture windows: explicit window ID/TTY, неверный TTY и старая app instance после завершения отклонены. Несколько tabs/splits в одном окне, TTY reuse, rename/reorder, одинаковые titles, generation/capture/shell epochs, persistent registry и локальный consent — NOT_RUN. Непереданные targets не раскрываются через MCP/IPC. AT-02/03/12/17, TE-C03/04/07.

## Фактический результат и продолжение

Host поддерживает локальные list/resolve diagnostics для запущенных Ghostty и Terminal.app. Apple Events адресуются к PID уже запущенного приложения; title/index не route key. Terminal.app tab TTY не равен устойчивой identity и может переиспользоваться. CLI diagnostic может показывать названия непереданных окон локальному пользователю, поэтому MCP/IPC его не вызывают. Session ID, grants и attach пока отсутствуют.

Следующий шаг — локальный выбор и consent, затем host-owned registry/opaque handle с generation и перепроверкой binding перед чтением/вводом. Ghostty discovery проверена в ревизии `58c1323`, Terminal.app discovery — в `7fa8e76` на ветке `te-e02`.
