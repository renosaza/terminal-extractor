# Terminal.app: discovery и retained text

## Результат

Реализовать typed Apple Events helper для verified enumeration и текстового чтения конкретной вкладки без focus-based routing.

## Приёмка

Читаются только разрешённые targets; версии/provenance/observed_at доступны. У tab нет стабильного `id`: binding учитывает window ID, tab TTY и generation, повторно проверяется перед чтением/вводом; `selected tab` без проверки не служит identity. Snapshot/retained scrollback не выдаётся за непрерывный журнал; history truncation/unknown start обозначены. Helper имеет timeout и не блокирует host Stop.

## Проверка

PARTIAL: read-only Terminal.app discovery перечислил fixture windows и разрешил точный app-instance/window-ID/TTY; неверный TTY и прежняя app-instance после завершения тестового процесса отклонены. `swift build`, `python3 Tests/integration/terminal_discovery.py` PASS на живом fixture. Две вкладки в одном окне, TTY reuse, неактивная вкладка, contents/history, очистка истории, Unicode, denied Automation и разрешённый read path — NOT_RUN. AT-03/04/08/17, TE-C01/03/04/07.

## Фактический результат и продолжение

[TerminalDiscovery](../../../Sources/TermexCore/TerminalDiscovery.swift) использует общий PID-targeted Apple Event reader и локальные `--list-terminal`/`--resolve-terminal`. Window ID и TTY возвращаются отдельно от display ordinal/title; `resolve` не выдаёт grant. У tab нет стабильного ID, TTY может переиспользоваться, поэтому эта проверка **не** служит binding для agent read/input до host-owned generation и lifecycle reconciliation. Следующий шаг — consent/registry и ограниченное чтение конкретной разрешённой вкладки с честной coverage. Проверена ревизия `7fa8e76` на ветке `te-e02`.
