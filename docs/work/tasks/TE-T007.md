# Local identity, grants и writer leases

## Результат

Ввести peer-checked private IPC, server-side client identity, отдельные read/control/close/clipboard grants и один agent writer на session.

## Приёмка

ClientInfo/name/request fields не дают прав. Grants привязаны к session generation и локальному consent; ревокация увеличивает epoch до cleanup. ACL применяется к read/search/original retrieval и mutations. Нет permissive socket/содержимого секретов в diagnostics.

## Проверка

PARTIAL: `swift build`, `swift run TermexExportFileCheck`, `python3 Tests/integration/check.py` PASS для текущей ветки; прежние `TermexRegistryCheck`, `TermexConfigCheck` и живой выбор проверены ранее. Проверены owner/mode socket, same-UID gateway, bounded/slow frame, отказ при лишнем `clientInfo` и отсутствие IPC-подключения при неизвестном `TERMEX_*`. Host держит до восьми peer-checked соединений: два запроса по одному socket, независимый второй клиент, отказ девятому и остановка при частичном frame прошли. Restricted `allowed_apps` не открывает Ghostty dialog; `access_status` нового connection пуст. В предыдущем живом выборе пользователь выбрал `scope=read`: host вернул один session ID/generation, тот же IPC connection увидел только его, другой — пустой список. Новый тест проверяет отказ `terminal_screen` без grant/token и Stop при восьми клиентах. Через 60 секунд простоя socket закрывается; отдельного теста с реальным ожиданием этого срока нет. Cross-UID отказ отдельно NOT_RUN: тестовый процесс работает под одним UID. Два клиента с конкурирующим control, stale token/epoch после реального consent, cross-session read, expired lease и race revoke/dispatch — NOT_RUN. AT-10/11/14, TE-C03/06/07.

## Фактический результат и продолжение

`LocalIPC` проверяет peer effective UID через `getpeereid` после connect/accept; при отказе host не завершает listener. Host назначает каждому принятому socket локальный UUID и закрывает socket при disconnect/ошибке/простое или остановке host. Gateway валидирует имена env preferences до подключения. Host-only AppKit выбор Ghostty записывает read/control scope за этим UUID; второй control для того же session ID отклоняется, при disconnect запись удаляется. После выбора host выдаёт grant token, привязанный к connection, session generation и epoch. Для opt-in `terminal_screen` host сверяет исполняемый файл peer с sibling `termex-mcp` по device/inode, token/read/clipboard grant и epoch до export и после него. Stable signed identity ещё нет, same-UID процесс не изолирован. `termex-host --stop` увеличивает epoch и удаляет все grants до ответа; начатый ранее dialog не может выдать grant после Stop. Input, close и остальной read/search пока закрыты.

Следующий шаг — живая проверка `terminal_screen`, signed gateway identity для release, per-session expiry/lease и ACL всех будущих read/search/input операций. Peer UID проверена в ревизии `e74c9dc`; длительное соединение, host-side connection UUID и промежуточный consent — в PR #4. Stop/token — в PR #5; одноразовый screen dispatch — на ветке `ghostty-screen-read`.
