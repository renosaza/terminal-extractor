# Local identity, grants и writer leases

## Результат

Ввести peer-checked private IPC, server-side client identity, отдельные read/control/close/clipboard grants и один agent writer на session.

## Приёмка

ClientInfo/name/request fields не дают прав. Grants привязаны к session generation и локальному consent; ревокация увеличивает epoch до cleanup. ACL применяется к read/search/original retrieval и mutations. Нет permissive socket/содержимого секретов в diagnostics.

## Проверка

PARTIAL: `swift build`, `swift run TermexRegistryCheck`, `python3 Tests/integration/check.py` PASS для текущей ветки; прежние `TermexConfigCheck` и живой выбор проверены ранее. Проверены owner/mode socket, same-UID gateway, bounded/slow frame, отказ при лишнем `clientInfo` и отсутствие IPC-подключения при неизвестном `TERMEX_*`. Host держит до восьми peer-checked соединений: два запроса по одному socket, независимый второй клиент, отказ девятому и остановка при частичном frame прошли. Restricted `allowed_apps` не открывает Ghostty dialog; `access_status` нового connection пуст. В живом локальном выборе пользователь выбрал `scope=read`: host вернул один session ID/generation, тот же IPC connection увидел только его, другой — пустой список. Новый тест проверяет последовательные Stop, epoch и сохранение доступности host. Через 60 секунд простоя socket закрывается; отдельного теста с реальным ожиданием этого срока нет. Cross-UID отказ отдельно NOT_RUN: тестовый процесс работает под одним UID. Два клиента с конкурирующим control, stale token/epoch после реального consent, cross-session read, expired lease и race revoke/dispatch — NOT_RUN. AT-10/11/14, TE-C03/06/07.

## Фактический результат и продолжение

`LocalIPC` проверяет peer effective UID через `getpeereid` после connect/accept; при отказе host не завершает listener. Host назначает каждому принятому socket локальный UUID и закрывает socket при disconnect/ошибке/простое или остановке host. Gateway валидирует имена env preferences до подключения и передаёт только три документированных ключа. Host-only AppKit выбор Ghostty записывает read/control scope за этим UUID; второй control для того же session ID отклоняется, при disconnect запись удаляется. После выбора host выдаёт grant token, привязанный к connection, session generation и epoch. Проверка token/scope есть в host, но session dispatch пока не вызывает её: read/input tools отсутствуют. `termex-host --stop` увеличивает epoch и удаляет все grants до ответа; начатый ранее dialog не может выдать grant после Stop. Это подготовительное состояние, `terminal_access=false`. Stable gateway identity и revoke/dispatch race ещё не проверены. Same-UID процесс не изолирован peer UID проверкой.

PARTIAL pending-consent Stop handling, 2026-09-25: host теперь передаёт ожиданию consent helper условие изменения grant epoch; после Stop ожидание должно завершиться и helper быть остановлен, а поздний ответ по-прежнему не может создать grant. `swift build --product termex-host` и `python3 Tests/integration/check.py` прошли; живой Stop при открытом AppKit dialog и его визуальное закрытие — NOT_RUN. Это не проверка revoke/dispatch race и не право на managed shell.

Следующий шаг — stable gateway identity, отдельные clipboard/close grants и применение token/scope/epoch непосредственно в read/control dispatch. Текущий token ещё не используется gateway для session operation. Peer UID проверена в ревизии `e74c9dc`; длительное соединение, host-side connection UUID и промежуточный consent — в PR #4. Stop/token на ветке `grant-revocation`.
