# Local identity, grants и writer leases

## Результат

Ввести peer-checked private IPC, server-side client identity, отдельные read/control/close/clipboard grants и один agent writer на session.

## Приёмка

ClientInfo/name/request fields не дают прав. Grants привязаны к session generation и локальному consent; ревокация увеличивает epoch до cleanup. ACL применяется к read/search/original retrieval и mutations. Нет permissive socket/содержимого секретов в diagnostics.

## Проверка

PARTIAL: `swift build`, `swift run TermexConfigCheck`, `python3 Tests/integration/check.py` PASS. Проверены owner/mode socket, same-UID gateway, bounded/slow frame, отказ при лишнем `clientInfo` и отсутствие IPC-подключения при неизвестном `TERMEX_*`. Host держит до восьми peer-checked соединений: два запроса по одному socket, независимый второй клиент, отказ девятому и остановка при частичном frame прошли. Restricted `allowed_apps` не открывает Ghostty dialog; `access_status` нового connection пуст. В живом локальном выборе пользователь выбрал `scope=read`: host вернул один session ID/generation, тот же IPC connection увидел только его, другой — пустой список. Через 60 секунд простоя socket закрывается; отдельного теста с реальным ожиданием этого срока нет. Cross-UID отказ отдельно NOT_RUN: тестовый процесс работает под одним UID. Два клиента с конкурирующим control, stale token/epoch, cross-session read, expired lease и race revoke/dispatch — NOT_RUN. AT-10/11/14, TE-C03/06/07.

## Фактический результат и продолжение

`LocalIPC` проверяет peer effective UID через `getpeereid` после connect/accept; при отказе host не завершает listener. Host назначает каждому принятому socket локальный UUID и закрывает socket при disconnect/ошибке/простое или остановке host. Gateway валидирует имена env preferences до подключения и передаёт только три документированных ключа. Новый host-only AppKit выбор Ghostty записывает read/control scope за этим UUID; второй control для того же session ID отклоняется, при disconnect запись удаляется. Это подготовительное состояние, а не доступ к терминалу: `terminal_access=false`, read/input tools нет, authenticated gateway, Stop и dispatch ACL ещё нет. Same-UID процесс не изолирован peer UID проверкой.

Следующий шаг — authenticated gateway identity и локальный Stop, затем read/control/close/clipboard grants с epoch и dispatch checks до любых session tools. Peer UID проверена в ревизии `e74c9dc`; длительное соединение, host-side connection UUID и промежуточный consent — на ветке `local-client-connections`.
