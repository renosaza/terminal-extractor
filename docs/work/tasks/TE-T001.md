# Проверить API установленного Terminal.app

## Результат

Создать безопасный probe dictionary, адресного чтения и ввода в отдельную тестовую вкладку. Записать OS/app versions и dictionary hash, поддерживаемые selectors и неизвестные возможности.

## Приёмка

Проверены window/tab/TTY mapping, retained contents/history, line submission и наличие либо отсутствие безопасного no-Enter/control-key пути. Доказано, что existing fixture сохраняет PID/переменную. Не использовать do shell script как замену живой вкладке или focus injection. Full native interactive gate либо закрыт evidence, либо остаётся явно открытым.

## Проверка

PARTIAL: словарь и версии прочитаны; две вкладки, смена focus, quotes/newlines, busy REPL и idle shell — `NOT_RUN`. Ничего не вводить в рабочие окна. AT-02/03/09/17, TE-C01..04/09.

## Фактический результат и продолжение

На macOS 27.0 (26A428) установлен Terminal.app 2.15 (build 488). `python3 probes/dictionaries.py` прочитал встроенный `Terminal.sdef`, SHA-256 `efc515ecd1bee050284942655a76654c84ff4c77f6cbe4704d7aafbabe8a92af`. Словарь объявляет `window.id`, `window.tabs`, `tab.tty`, `tab.contents`, `tab.history`, `tab.busy` и `do script` с параметром `in` типа `tab`/`window`. У `tab` нет собственного стабильного `id`; `window.index` описан как порядок спереди назад. Отдельной команды raw paste или `send key` словарь не объявляет. Это `known` только для декларации API, не для фактической доставки или полноты истории.

Проверка живой вкладки и сохранения PID/переменной `NOT_RUN`: Apple Events/TCC и рабочие окна не трогались. `sdef` из активного Command Line Tools не запускается без полного Xcode; probe читает встроенный файл напрямую. Следующий шаг — отдельные тестовые окна и адресный Apple Events probe после локального разрешения; no-Enter/control-key gate остаётся открытым. Проверенный исходный revision: `6dee2b5` плюс текущие изменения ветки `te-e01`.
