# Terminal.app: явное новое окно и binding

## Результат

Реализовать native-new и общий launch path для будущего managed attach command в обычном Terminal.app.

## Приёмка

Сначала доказан рабочий creation path для установленного Terminal.app: `make new window` на 2.15 вернул -10000 и оставил пустое окно в TE-T001. Запуск только по explicit new/permission; ровно созданная вкладка и её TTY связываются с registry до разрешения ввода. Частично созданное окно удаляется либо явно сообщается как orphan; соседняя вкладка не выбирается. Existing не перезапускается. Initial cwd/launch arguments проверены и передаются безопасно, не становятся arbitrary AppleScript source; user profile/font/theme сохранены.

## Проверка

PARTIAL feasibility: на Terminal.app 2.15 `make new tab at end of tabs` в живом fixture window вернул -10000, и в выбранном окне вторая вкладка не появилась. Тест `open -a Terminal fixture.command` обнаружил отдельные восстановленные окна; он не доказывает native-new binding. AppleScript `close window` вернул успех, но тестовое окно оставалось видимым; при штатном quit Terminal.app запросил локальное подтверждение завершения процессов. Пользователь выбрал Terminate Processes; после этого приложение не запущено и discovery возвращает пустой список. Рабочий creation/cleanup path, необычный cwd с пробелами/quotes и окно закрыто до ready — NOT_RUN. Нельзя тихо выбрать соседнее. AT-01/02/03, TE-C02/03/06.

PARTIAL one-window creation, 2026-09-25, checked code revision `c91ac74`: после отдельного согласия пользователя Terminal.app был остановлен и discovery давал 0 вкладок. Единственная попытка `open -a /System/Applications/Utilities/Terminal.app <private fixture.command>` создала одно окно/одну вкладку; fixture `zsh -f` записал только свой TTY в каталог 0700, и `TerminalDiscovery.resolve` подтвердил точную тройку app instance/window ID/TTY. Это новый временный shell, не managed attach, не перенос существующей сессии и не product view binding. Адресный AppleScript `close` после повторной проверки window ID, единственной вкладки и TTY вернул успех, но непосредственно после него discovery по-прежнему видело одну вкладку; автоматический cleanup не подтверждён. Повторного запуска, `quit`, отправки команд в окно и выбора по фокусу не было. Позднее read-only проверки дали 0 вкладок в discovery и 0 окон в Terminal.app; способ закрытия не установлен. После этого удалены только два файла private fixture и его пустой каталог. Initial cwd/launch arguments, надёжный автоматический cleanup, failure-before-ready и product binding остаются `NOT_RUN`.

PARTIAL binding guard, 2026-09-25: `TerminalDiscovery.snapshot` теперь сохраняет app instance, IDs всех окон (включая пустые) и tab choices одним обходом. `newWindow` принимает до/после snapshot и TTY, записанный только private fixture; принимает ровно одну новую одновкладочную window с тем же app instance, отклоняя старый/пустой window ID, повтор TTY, смену процесса и некорректный TTY. `swift run TermexRegistryCheck` и `swift run -c release TermexRegistryCheck` прошли на синтетических положительных/отрицательных наборах; live Terminal.app с новым helper не запускался. Выбор ещё требуется перепроверять через `resolve` перед действием; snapshot не атомарен относительно внешнего закрытия/reuse TTY и не предоставляет grant/generation. Это не product launch или надёжный cleanup.

PARTIAL live binding fixture, 2026-09-25, checked code revision `c7dfa21`: после отдельного согласия на ещё одну попытку создано ровно одно новое тестовое окно Terminal.app. Private `zsh -f` fixture записал только свой TTY; до и непосредственно перед запуском owner-backed attach проверена точная тройка app instance/window ID/TTY без выбора по фокусу. Пользователь сообщил все пять статусов owner fixture `PASS` после ручного detach. Одноразовая zsh-обёртка затем отказала на присваивании read-only переменной `status`, поэтому её файл exit-кода отсутствует и итоговый код завершения не подтверждён. Read-only проверка после отчёта видит одно окно; автоматическое закрытие не проверено. Это не product binding/grant, не перенос existing shell и не доказательство защиты от последующего TTY reuse.

FOLLOW-UP cleanup, 2026-09-25: последующая read-only проверка дала 0 окон Terminal.app; способ закрытия не установлен. После проверки owner/type и точного состава private fixture удалены только его три файла и пустой каталог. Автоматическое закрытие окна этим не доказано.

PARTIAL second authorized window fixture, 2026-09-25, checked code revision `5b9452c`: перед запуском owner fixture ещё одно новое тестовое окно было единственным в Terminal.app; app-instance/window-ID/TTY и `resolve` совпали с private TTY непосредственно до разрешения attach. Пользователь сообщил шесть статусов `PASS`, включая `view_client`; отдельный файл одноразовой обёртки содержал exit code `0`. Последующая read-only проверка дала 0 окон; способ закрытия не установлен. После проверки точного состава удалены только четыре файла private fixture и пустой каталог. Это по-прежнему не product native-new/cleanup или grant.
