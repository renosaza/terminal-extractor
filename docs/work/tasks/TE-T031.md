# Реализовать open/attach/execute/send/release/close

## Результат

Связать mutation tools с exact target, local grants, idempotency и native/managed capability-specific transport.

## Приёмка

Existing/new не подменяются. Execute ждёт ограниченно и возвращает command record; send сообщает delivery, не fake exit. Release сохраняет shell, close отдельно разрешается. Unsupported/invalid request отклоняется до side effect. Клиент не может передать себе grant или подменить socket/TTY.

## Проверка

Scope текущего среза — только адресный release существующего grant. Полная карточка остаётся doing: open/attach/execute/send/close, partial delivery, busy/unknown prompt и revoke midqueue ещё не реализованы. AT-01/02/03/05/09/10/11/12, TE-C02..04/07.

PARTIAL: 2026-09-24 ревизия `6f5fa60`, `swift build`, `python3 Tests/release_check.py`, `python3 Tests/integration/check.py` и `git diff --check` — PASS. Grant-store check покрывает точный отзыв, stale token/generation, чужого клиента, соседнюю session и освобождение writer. Gateway check покрывает replay после нового consent, conflict, лимит 256 и неопределённый IPC-ответ без повторной отправки. Реальный MCP gateway проверен с синтетическим host: success и replay, без UI или доступа к терминалам. Интеграционный тест проверяет отказ без grant и неверные входные MCP/IPC поля. Независимое read-only review не нашло блокирующих замечаний. Live release после реального consent и Stop во время export — NOT_RUN; synthetic consent не считается живой проверкой. Сборка дала предупреждения linker о путях CommandLineTools, без ошибок.

## Фактический результат и продолжение

После сравнения штатных `exec_command`/`write_stdin` с [MCP-контрактом](../../architecture/mcp-contract.md) выбран `terminal_release`: он закрывает разрыв в управлении доступом, не дублируя запуск нового процесса и не требуя unsafe input в уже работающую программу. Host снимает grant только указанного connection/session/generation/token; registry binding и shell сохраняются. Gateway хранит ограниченный connection-local request cache, поэтому старый retry после повторного consent не удаляет свежий grant. Локальный Stop остаётся отдельным каналом; release не прерывает текущий export. TE-C01..09 сохранены, пользовательские terminal/clipboard contents для этого среза не извлекаются.

Будущий минимальный command API — execute + continue с optional explicit input и bounded output/status wait. Это предложение интерфейса; пока нет command evidence, control grant и проверенного prompt gate, tools не объявляются. Зависимости карточки относятся к полному mutation scope, не к уже изолируемому отказу от существующего grant. Следующий шаг — завершить открытые проверки Stop/export в TE-T015; ввод не открывать на основании одного snapshot.
