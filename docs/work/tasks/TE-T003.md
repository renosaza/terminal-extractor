# Прототипировать zsh events без изменения shell-семантики

## Результат

Доказать получение preexec/precmd boundaries, exit code, shell epoch и readiness; выбрать bootstrap, сохраняющий пользовательский startup order.

## Приёмка

`$?` снимается до helper; hook arrays не заменяются; rc не source дважды; ZDOTDIR/login/interactivity сохранены. Выявлены limits continuation, ZLE buffer, background output, exec/exit и вложенного SSH/REPL. Есть схема side-channel events и stream fences с ordering, а не доверие prompt regex.

## Проверка

PARTIAL: isolated zsh profiles с aliases/functions/cd/export и существующими hooks проверены; `exec`/`exit` проверены только по отсутствию hook end event, background output — по одному контролируемому interleaving. Ошибки prompt, continuation, ZLE buffer и вложенные SSH/REPL — `NOT_RUN`. Existing busy session не инструментируется скрыто. AT-05/06/07, TE-C02/04/06.

## Фактический результат и продолжение

`python3 probes/zsh/probe.py` прошёл на zsh 5.9/macOS 27.0 (26A428). Probe создаёт временные original/shim `ZDOTDIR`, не читает и не меняет пользовательские rc. Non-login startup прошёл `.zshenv → .zshrc`, login — `.zshenv → .zprofile → .zshrc → .zlogin → .zlogout`, каждый файл один раз. В одном живом shell сохранились alias, функция, `cd`, `export`; существующие preexec/precmd hooks вызывались. Для восьми тестовых команд preexec/precmd дали 8 start/8 end после начального precmd; `exit` дополнительно вызвал preexec без соответствующего precmd. Ground truth кодов: `0,0,0,0,0,1,1,0` для alias/function/cd/export/print/false/pipeline/print. Прототип сохраняет `$?` в начале precmd, пишет side-channel event с sequence/shell epoch и stream fence с nonce. Это локальный proof ordering, не готовый защищённый транспорт.

Не доказаны потеря/повтор events, граница смешанного background output, continuation/ZLE и вложенные программы; в этих состояниях будущий runtime должен возвращать `unknown`. Следующий шаг — расширить fixture только на эти риски и согласовать bootstrap перед интеграцией. Проверенный исходный revision: `6dee2b5` плюс текущие изменения ветки `te-e01`.

PARTIAL `exec`/`exit`, 2026-09-24: в отдельном временном HOME/ZDOTDIR fixture `exec /usr/bin/false` и `exit 7` дали по одному `start` sequence 1 и только начальный `end` sequence 0; matching hook end для команд нет. Test harness увидел коды процессов 1 и 7, но это не shell event evidence, доступное будущему product API. До lifecycle reconciliation статус этих команд остаётся `unknown` по TE-C04. `python3 probes/zsh/probe.py` прошёл дважды; пользовательские rc и terminal pane не читались и не менялись. Это не реализует authenticated events, bootstrap или надежный exit status.

PARTIAL background interleaving, 2026-09-24: в том же disposable zsh fixture фоновая job первой команды ждала private release file. Вторая команда освободила её и дождалась завершения; фоновый маркер оказался между `start|2` и `end|2` fences, перед маркером самой второй команды. `python3 probes/zsh/probe.py` прошёл 20 повторов. Интервал второй команды поэтому не доказывает владение каждым байтом её foreground process; `attribution` остаётся `interleaved|unknown` по контракту. Это не product journal, не проверка конкурентных произвольных jobs и не доказательство полноты capture.
