# Активные ограничения

Источник пользовательских требований — постановка владельца от 2026-09-23; технические уточнения раскрыты в [PRD](product/prd.md). Ограничения относятся к v1; изменения scope требуют решения владельца.

| ID | Запрещённое действие | Scope / основание | Исключение или условие пересмотра |
|---|---|---|---|
| TE-C01 | Подменять Terminal.app/Ghostty веб-терминалом, screenshots или OCR | Все пути чтения; требование пользователя | Нет в v1 |
| TE-C02 | Создавать отдельный рабочий shell/SSH exec на каждый ввод или выдавать новую сессию за захваченную старую | Живая сессия; требование пользователя | Служебные процессы допустимы; новый shell — только явное создание |
| TE-C03 | Направлять ввод по текущему фокусу, порядковому номеру окна или автоматически выбирать соседнюю сессию | Изоляция выбранного окна; требование пользователя | Нет; нужны session ID, generation и проверка привязки |
| TE-C04 | Выдавать предположение о завершении за подтверждённый exit status, а неполный лог за полный | API статусов и истории; технический контракт | Возвращать unknown, evidence и coverage |
| TE-C05 | Уничтожать оригинал при сжатии, сжимать статус/ID/актуальное интерактивное состояние с потерями | Запрошенное сжатие не отменяет корректность | Retention/удаление по локальной политике явно отражаются |
| TE-C06 | Самовольно менять глобальные AGENTS.md, shell rc, профили терминалов, хоткеи, TCC или устанавливать зависимости | Репозиторная задача не разрешает изменения рабочего Mac | Только отдельное локальное согласие пользователя |
| TE-C07 | Предоставлять агенту доступ к непереданным сессиям или продолжать ввод после отзыва прав | Изоляция и совместное управление | Новое локальное разрешение |
| TE-C08 | Называть Windows/Linux, произвольные shell и удалённую установку частью обязательного v1 | Пользователь сузил scope до macOS | Отдельное расширение PRD |
| TE-C09 | Использовать TTY-инъекцию, обход TCC, root/процессную инъекцию как скрытый fallback | Предлагаемый безопасный контракт macOS | Требуется отдельное рассмотрение; в v1 не реализовывать |

TE-C01..05 вытекают из требований и их проверяемости. TE-C06..09 фиксируют границу этой спецификации, а не утверждают наличие системной песочницы. Документ не предоставляет новых прав доступа. См. [безопасность](architecture/security.md).
